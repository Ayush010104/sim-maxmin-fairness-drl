Deep RL Framework for Max-Min Fairness Optimization

I designed a deep reinforcement learning framework for max-min fairness optimization — a class of problems where the goal isn't to maximize total throughput, but to lift the worst-performing participant in a system, so resources go where they're actually needed rather than where they're cheapest to deliver. I validated this framework on a wireless communications problem: beamforming control in Stacked Intelligent Metasurfaces (SIM), a next-generation multi-layer programmable surface that reshapes radio waves directly in the air.

01 — The control loop

Constarined Optimization problem modeled as sequential decision-making process

A constrained optimization problem is represented as a Markov decision process (MDP). The state encodes the current optimization variables, and the RL policy selects an action that specifies how those variables should change. The environment applies the update, evaluates the resulting solution, and returns feedback to guide subsequent decisions.

STATE → INCREMENTAL ACTION → UPDATED SOLUTION → EVALUATE → REPEAT
02 — The reward

Fairness needs more than "help the worst case"

A reward based solely on the worst-performing objective is well aligned with fairness, but it provides a limited learning signal: improvements to objectives outside the current bottleneck may not be adequately reflected in the reward. Incorporating the geometric mean of all objectives addresses this limitation by encouraging coordinated improvement across the system. However, the geometric mean alone does not guarantee a satisfactory floor for the weakest objective, as improvements across the system can coexist with an unacceptably low minimum value. We therefore combine both terms in a composite reward: the geometric mean promotes system-wide improvement by providing a broader learning signal, while the minimum objective reinforces the need to improve the bottleneck. This complementary reward design creates a more informative optimization landscape.

Every arrow points everywhere, tilted toward whichever objective is behind — every improvement is rewarded, and the worst-off objective gets the extra pull.

03 — The system

Grounding the framework in stacked intelligent metasurfaces

The previous two sections described the framework in the abstract: a generic state, a generic reward. In practice, I apply it to max-min fair beamforming in a stacked intelligent metasurface (SIM) system — a base station transmits through cascaded passive metasurface layers that each reshape the signal's phase before it reaches the users, while a power-split ratio controls how the transmit power is divided. The optimization problem is to choose a phase configuration across all layers and a power split that maximizes the composite reward from the previous section, subject to the physical constraint that every phase value must lie on the unit circle and the power split must stay within the system's power budget.

These are exactly the "optimization variables" from the control loop: together (θ, p) form the state sₜ — but the framework doesn't treat them equally. Phase is the main variable: it carries most of the optimization burden, so the policy nudges it incrementally (Δθ). Power is secondary — it needs much less variance from step to step, so instead of nudging it, the network just outputs its new value directly. The next section shows how each one is kept well-behaved: a projection rule for phase, a regularizer for power.

04 — Implementation & Results

From constraint to code to a working system

Three pieces turn the framework above into something that actually runs: a projection rule that keeps every action physically valid, a network architecture that executes it, and the real results it produces.

Keeping both actions well-behaved

The Δθ phase delta isn’t computed the naive way. Each phase value in the system has to sit exactly on a unit circle — a hardware constraint. A naive approach lets the network propose any raw adjustment and projects it back onto the circle after the fact, but that creates a problem: countless different raw adjustments can land on the exact same point, so the stored action carries no information about which one actually happened. Instead, the porposed framework stores the IGPD (In Graph Proposed Delta Action) — the actual step from the old point to the new one on the circle — so the critic always learns from an action that genuinely explains the transition it caused.

discarded: raw proposal stored: actual move on the circle

The network can propose anything — only the real, physically valid step from old phase to new phase is ever stored as the action.

Store what happened, not what was attempted.

Power has no such constraint: softmax already guarantees it always sums to the power budget. What power needs instead is a nudge toward fairness, since nothing in its own objective stops the network from starving the weakest user. I add a cross-entropy regularizer to the actor's loss that pulls the power head's output toward a target distribution proportional to each user's inverse rate — the worse a user is doing, the more that target asks for.

One actor, two control problems

Phase control and power control need opposite things from a learning algorithm. Phase has many good configurations to discover, so it benefits from exploration — the system should try varied options before settling. Power allocation is the opposite: it needs precise, stable control, since jittery power swings destabilize everything else being learned. I built a single actor network with two heads trained differently: a stochastic, exploration-driven head (Soft Actor-Critic) for phase, and a deterministic, precision-driven head (DDPG) for power — unified under one shared critic, rather than splitting the problem into two separate agents.
